## 2026-09-20 17:20 (+03:00) - Found and fixed the REAL cause of the non-functional "Log out" button

- User reported logout still didn't work: it called GET /logout but then silently logged them back in without credentials on the next visit.
- **Root cause #1 (config)**: Spring Security auto-registers a `DefaultLogoutPageGeneratingFilter` whenever form login is used with no custom login page - this filter has its own hardcoded GET /logout matcher and runs *after* our custom `LogoutFilter` in the chain, but our `LogoutFilter` was never actually matching the request, so control fell through to it and it returned a "Confirm Log Out?" HTML confirmation page (200 OK) instead of a 204 - the session was never invalidated, so the browser's live JSESSIONID let the subsequent /oauth2/authorize silently reissue a fresh code with no login prompt.
- **Root cause #2 (the real bug, once #1 was traced further)**: the backend process serving requests was running `collectb-platform-api` via a standalone `mvnw spring-boot:run` invocked directly inside that module's directory. Maven resolves the `collectb-identity` dependency in that mode from the **local `~/.m2` repository**, not from the sibling module's freshly-compiled `target/classes` - and an earlier `mvn install` in this session had installed a stale pre-logout-fix jar. So every restart of the backend after editing `AuthorizationServerConfig.java` kept running the *old* logout code, no matter how many times the config was edited/recompiled via `mvn test`.
- **Fix**: ran `mvnw -pl collectb-identity,collectb-catalog -am install -DskipTests` to reinstall both library modules' current source into the local repo, then restarted `collectb-platform-api` via `spring-boot:run` again so it picked up the real jar.
